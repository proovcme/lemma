# Установка и эксплуатация

## Первая установка

```sh
git clone --branch v0.1.1 https://github.com/proovcme/lemma.git
cd lemma
./scripts/init.sh admin@example.org
docker compose up --build -d --wait
docker compose ps
```

Войдите на `http://localhost:8080` по логину `0001` и паролю `ADMIN_PASSWORD` из `.env`. Этот файл создаётся с правами 600 и не перезаписывается повторным запуском. Сначала настройте подразделения и сотрудников, затем создайте проект и задачи. При старте применяются миграции; существующий администратор и его пароль сохраняются.

Пароли MariaDB в `.env` задают учётные записи при первом создании volume. Для смены пароля существующей базы сначала смените его в самой MariaDB, затем в `.env`.

## Домен и HTTPS

Направьте DNS на сервер, откройте порты 80/443 и настройте `.env`:

```dotenv
APP_URL=https://lemma.example.org
LEMMA_SITE=lemma.example.org
HTTP_PORT=80
HTTPS_PORT=443
```

Затем `docker compose up -d`. Caddy получает и обновляет сертификаты. Если HTTPS завершается на вашем reverse proxy, настройте его отдельно; приложение должно получать правильный внешний `APP_URL`.

## Резервные копии

```sh
./scripts/backup.sh
./scripts/backup.sh /mnt/backup/lemma
```

На время копирования приложение останавливается и автоматически запускается после завершения. В копию входят SQL, файлы `storage`, версия кода, контрольные суммы и `.env` с ключом шифрования. Это конфиденциальный архив: храните его в защищённом месте вне сервера. Оставляйте достаточно свободного диска и регулярно проверяйте восстановление.

```sh
./scripts/restore.sh /mnt/backup/lemma/20260918T120000Z --yes
```

Восстановление заменяет все текущие данные. Сначала используйте ту же версию приложения, на которой сделана копия. На новом сервере перенесите конфигурацию из `environment.env` в `.env`, скорректируйте адрес и запустите пустую установку. Ключ `APP_DATA_KEY` должен совпадать с ключом резервной копии. Скрипт проверяет контрольные суммы и ключ до изменения базы. При сбое восстановления приложение остаётся остановленным до устранения причины.

## Обновление

Обновляйтесь на конкретный опубликованный тег, прочитав описание релиза. Сначала сделайте копию, затем остановите приложение и смените код:

```sh
./scripts/backup.sh
docker compose stop web lemma
git fetch --tags origin
git checkout v0.1.1
docker compose up --build -d --wait
```

В примере указан текущий релиз; замените тег на выбранную версию. Миграции выполняются при старте. Если обновление не удалось, вернитесь к прежнему тегу, пересоберите контейнеры и восстановите предшествующую копию. Один откат Git не отменяет миграции базы. Пользовательские изменения кода храните в собственной ветке.

## Почта

SMTP по умолчанию выключен. Задайте `MAIL_ENABLED=1`, `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_FROM_EMAIL`, `MAIL_ENCRYPTION` в `.env` и выполните `docker compose up -d`. Также доступны настройки SMTP в приложении. Отправка выполняется очередью:

```sh
docker compose exec -T lemma php scripts/send_mail_queue.php
```

Автоматического отправителя в первом выпуске нет. Настройте периодический запуск этой команды средствами вашего сервера после проверки SMTP.

## Отдельные инструменты

`ATLAS_URL` может указывать на ваш отдельный Атлас. По умолчанию просмотрщик не поставляется. Калькулятор и PDF-редактор не нужны для запуска Леммы. Каталоги с документами на файловом сервере потребуют отдельного монтирования в контейнер; путь Windows/UNC сам по себе не делает папку доступной в Linux.

## Диагностика

```sh
docker compose ps
docker compose logs --tail 100 lemma web
```

Не публикуйте `.env`, дампы и журналы с рабочими данными в GitHub Issues. Укажите версию из `manifest/release.json`, шаги воспроизведения и обезличенное сообщение ошибки. Рабочие данные находятся в volumes `database` и `storage`. Команда `docker compose down -v` удаляет их; для обычной остановки используйте `docker compose stop`.
