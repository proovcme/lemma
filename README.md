# Лемма

[![Проверки](https://github.com/proovcme/lemma/actions/workflows/ci.yml/badge.svg)](https://github.com/proovcme/lemma/actions/workflows/ci.yml)

**Рабочая система для проектной организации на вашем сервере.** Проекты, команда, задачи с проверкой результата, сроки, трудозатраты и документы в одном месте.

[Попробовать демо](https://locia.work/lemma/) · [Установка](docs/INSTALL.md) · [Релизы](https://github.com/proovcme/lemma/releases) · [Сообщить о проблеме](https://github.com/proovcme/lemma/issues)

## Что умеет

- Вести проекты, стадии и разделы, назначать руководителей и проектные команды.
- Передавать задачи исполнителям, согласовывать выдачи, принимать результат или возвращать на доработку с сохранением истории.
- Показывать сотруднику «Мой день», руководителю — сроки, загрузку, просрочки и план-факт времени.
- Хранить вложения задач и документы базы знаний, обсуждения и версии документов.
- Управлять доступом по ролям; вести команду, отчёты, периодические оценки и управленческие показатели.
- Выгружать отчёты, создавать резервную копию и восстанавливать собственную установку.

Система работает самостоятельно. Данные хранятся на сервере владельца установки. Установка автономна.

## Установить для работы

Нужны Linux, Docker Engine и Docker Compose v2. Рекомендуем начать с 2 CPU, 4 ГБ RAM и 10 ГБ диска; объём вложений учитывается отдельно.

```sh
git clone --branch v0.1.0 https://github.com/proovcme/lemma.git
cd lemma
./scripts/init.sh admin@example.org
docker compose up --build -d --wait
```

Откройте **http://localhost:8080**. Логин администратора — `0001`, случайный пароль находится в `ADMIN_PASSWORD` файла `.env`. Сохраните его в менеджере паролей. В рабочей базе нет демонстрационных сотрудников и проектов.

[Домен и HTTPS, обновления, почта, резервные копии →](docs/INSTALL.md)

## Запустить локальное демо

```sh
docker compose -f compose.demo.yml up --build -d
```

Откройте **http://localhost:8081** и выберите роль. Демо использует вымышленные данные и пересоздаётся после перезапуска. Рабочий режим использует постоянную MariaDB; демо — SQLite и временное хранилище. Это разные установки.

Демо на locia.work может обновляться по отдельному графику. Версия скачанного дистрибутива указана в `manifest/release.json`.

## Первый выпуск

`v0.1.0` — первый самостоятельный выпуск Леммы на основе ядра `2026.06.11.197`. В поставку входят код, миграции, инструкции и вымышленные демонстрационные данные.

Атлас, сметный калькулятор и PDF-редактор доступны отдельно на [locia.work](https://locia.work/). При необходимости внешний Атлас задаётся через `ATLAS_URL`. Серверная подготовка BIM-моделей, Revit API, Web Push и Windows-инсталлятор не входят в этот выпуск. Реестр выпусков СОД с неизменяемыми снимками файлов пока не реализован; обычные вложения и база знаний доступны.

## Для разработчиков

PHP 8.4, PDO, MariaDB 11.4, серверные HTML-шаблоны, JavaScript и CSS; без обязательного frontend-фреймворка. Caddy завершает HTTPS. Каталоги `app/`, `config/`, `database/`, `public/`, `scripts/` содержат исходники; наружу раздаётся только `public/`.

```sh
php tests/run.php
python3 scripts/audit-public.py
```

CI проверяет PHP, бизнес-регрессии, чистую установку MariaDB, вход, сохранение данных при перезапуске, реальное резервное копирование и восстановление SQL и файлов, запуск демо и его данные.
