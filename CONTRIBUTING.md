# Участие

Для ошибки приложите версию, шаги, ожидаемый и фактический результат. Используйте вымышленные данные. Изменения предлагайте небольшими pull request с подходящей проверкой.

Перед изменением бизнес-логики запустите `php tests/run.php`. Для изменения миграций, установки, резервного копирования или Docker дождитесь полного CI. В UI сохраняйте существующие общие стили, CSRF-защиту, серверные проверки доступа и рабочие сценарии ролей.

## Обновление общего ядра

У Леммы отдельные версии и релизы. Исправление сначала оформляется как проверяемый патч; затем переносится в другую поддерживаемую ветку продукта, если оно относится к общему ядру. В `manifest/release.json` фиксируется базовый коммит. Нельзя переносить дампы, настройки серверов, runtime storage или Git-историю внутреннего продукта.

Каждый перенос проходит аудит публикуемых файлов, бизнес-тесты и установку/backup/restore в CI. Интерфейс, примеры и состав публичного дистрибутива проверяются отдельно. Автоматической синхронизации с внутренними репозиториями нет.
